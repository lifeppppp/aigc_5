# 烁的问答接口与百炼接入

当前版本有真实可操作的对话面板。chat-config.js 的 endpoint 留空时，仅使用有明确标识的本地演示回复。演示内容包括当日计划、学习任务步骤模板和曲率讲解，自由问答等待模型接入。

## 前端配置

将 chat-config.js 中 endpoint 设置为团队后端的 HTTPS 地址，例如 https://你的后端域名/api/study-chat。前后端在同一域名时也可以填写 /api/study-chat。

GitHub Pages 仅托管静态文件，模型调用由 Python 后端处理。API Key 使用服务器环境变量保存。前端代码、仓库、聊天请求均不应包含百炼 API Key。

跨域访问时，后端需要允许该 Pages 站点的 Origin，处理 OPTIONS 与 JSON POST。当前跨域请求不携带 Cookie。团队使用登录鉴权时，应按正式应用的鉴权机制扩展适配器。

## 请求

POST，Content-Type 为 application/json。

请求示例
{
  "message": "请帮我拆解这件学习任务",
  "history": [
    {"role": "user", "content": "今天先做什么？"},
    {"role": "assistant", "content": "先看一下今天的待办。"}
  ],
  "context": {
    "date": "2026-11-24",
    "tasks": [
      {
        "id": "demo1",
        "title": "复习曲率公式，完成两道例题",
        "type": "学习",
        "done": false,
        "time": "20:00",
        "requirements": "保留求导过程"
      }
    ],
    "focusedTask": null
  }
}

history 为本次问题之前的最近 12 条成功对话消息。
从任务详情入口打开时，focusedTask 是该任务的上述结构。
上下文包含所选日期的待办，手记正文不会自动上传。

## 成功响应

HTTP 200，Content-Type 为 application/json。

{"reply": "这里填写给用户的学习回答。"}

后端负责调用百炼、添加学习辅助系统提示词并返回 reply。
服务错误返回非 2xx 状态。前端会保留问题，允许重试。
请求超时为 45 秒，对话仅在当前页面会话内保留。

## 后端职责

校验输入和访问权限，限制请求频率与长度，保管密钥。
由服务端构建 system instruction，聚焦课程讲解、习题分析、笔记整理和复习规划。
将上传资料和用户任务作为待分析内容处理。
要求模型清楚表达公式、给出必要步骤，并避免编造参考资料。
前端默认按纯文本渲染回答，确保回复中的 HTML 不会执行。

此版本尚未接入真实百炼调用。接入时将 endpoint 指向团队正式的 Python 后端即可使用现有面板。
