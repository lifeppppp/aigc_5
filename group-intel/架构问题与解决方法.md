# 服务器架构：问题与解决方法

> 组内汇报素材。每条都注明**代码位置**或**控制台位置**，可以当场验证；末尾单独列出「还没验证的」，别把没跑通的写成跑通了。
> 记录时间：2026-11-21。

## 〇、整体架构

```
组员/评委的浏览器、手机            我们的 ECS（杭州，2C2G，Ubuntu 20.04）              阿里百炼
┌──────────────────────┐   HTTP    ┌────────────────────────────────────┐  HTTPS   ┌────────────┐
│ web/  （服务器托管）  │ ────────> │ FastAPI + uvicorn :8000            │ ───────> │ qwen3.7-plus │
│ local/launcher.py 壳 │ 8000 端口 │  server/app.py  ── 校验 X-Client-Token │  兼容模式   │         │
└──────────────────────┘           │   ├─ server/summarize.py 提示词+解析  │ <─────── └────────────┘
                                   │   ├─ server/llm.py        唯一持 Key 处 │  结构化 JSON
钉钉群 ── Stream ──> server/dingtalk_bot.py（收 @机器人）                    │
钉钉群 <── 加签 webhook ── server/dingtalk_push.py（回写结果）              │
                                   │ /opt/groupintel/.env  600 权限，只有这台机器有 │
                                   └────────────────────────────────────┘
```

一句话：**客户端里没有任何密钥，密钥只活在服务器上那台机器的 `.env` 里**，这是整个架构的出发点，下面一半的问题都是它的副作用。

## 一、凭据与信任边界

| 问题 | 为什么是个问题 | 解决方法 | 代码/位置 |
|---|---|---|---|
| API Key 会随客户端外泄 | 软件要发给组员和评委，前端里的任何字符串都能被 F12 看到；百炼 Key 一旦外泄就是别人刷你们的余额 | Key 只写在服务器 `/opt/groupintel/.env`，客户端只连我们的中转服务，由服务端带上 `Authorization: Bearer` 去请求百炼 | `server/llm.py:12-19`（读环境变量）、`server/groupintel.service`（`EnvironmentFile=`） |
| 中转站自己暴露在公网，等于免费算力接口 | `http://IP:8000` 谁都能访问，被扫到就烧钱 | 自定义请求头 `X-Client-Token` 与服务端 `CLIENT_TOKEN` 比对，不匹配直接 401 | `server/app.py:20-24` |
| **坑：`CLIENT_TOKEN` 留空等于不设防** | 校验逻辑是"服务端没配期望值就放行"，方便本地调试，但公网忘记填就是裸奔 | 部署时**必须**填一串长随机字符；`.env.example` 里已写成醒目占位 | `server/app.py:21-22`、`.env.example` |
| Key 泄露之后怎么办 | 共用 root 意味着组员技术上能看到 Key（见第五节） | 百炼控制台重置 Key → 改 `.env` → `systemctl restart groupintel`，老 Key 立即失效 | README 第二章 |

局限说清楚：`X-Client-Token` 存在浏览器 `localStorage`（`web/app.js:3-6`），它**不是身份认证**，只能挡住"随手拿到地址的陌生人"，挡不住铁了心扒客户端的人。小组实验够用，真要做得靠独立账号 + 服务端会话。

## 二、平台硬限制（不是 bug，查过官方文档）

| 限制 | 影响 | 我们的做法 |
|---|---|---|
| 钉钉**不允许**第三方程序静默拉取群内全部历史消息；全量存档要企业「会话存档」+ 资质 | 不能"一键整理整个群的历史" | 两条合规路：① Stream 模式收 **@机器人** 的消息（`server/dingtalk_bot.py`，AppKey/AppSecret 即 ClientId/ClientSecret，不需要公网回调地址和备案）② 客户端手动粘贴/上传记录。**演示走 ②**，最稳、不依赖审核 |
| 大陆 ECS 用 80/443 对外提供网页需要 **ICP 备案** | 不能直接用 `http://IP/` 这种好看地址 | 走非标端口 **8000**，安全组单独放行；`uvicorn --host 0.0.0.0 --port 8000` |
| 非 `localhost` 的 **HTTP** 源不满足 PWA 安装条件（service worker 需要安全上下文） | 浏览器不弹「安装应用」，做不到"下载过的软件"那种观感 | 现阶段：电脑用 `local/launcher.py` 起独立应用窗口（`--app=` + 独立 `--user-data-dir`），手机「添加到主屏幕」。真安装包列为下一步（pyinstaller 出 exe；PWABuilder 出 apk 需要先有 https） |

## 三、运行时与镜像

- **Ubuntu 20.04 自带 Python 3.8，代码里的新语法会让服务连启动都到不了。**
  `server/app.py` 原来写的是 `model: str | None`（3.10+）和 `messages: list[dict]`（3.9+）。Pydantic 在**定义模型类时就会真去求值注解**，所以 3.8 下不是运行到某个接口才报错，而是 `import app` 立刻 `TypeError`，`systemctl` 只显示启动失败。
  **解决**：改成 `Optional[str]` / `List[dict]`（`server/app.py:5,28-36`），并全仓 AST 扫描确认 7 个 py 文件里没有其他 3.9+/3.10+ 写法。**决定：不动服务器配置，改代码兼容。**
- **依赖版本不用手工钉。** 查过 PyPI 的 `requires_python`：3.8 上 pip 会自动解析到最后支持它的 **fastapi 0.124.4 / pydantic 2.10.6 / uvicorn 0.33.0**，行为与新版本一致。
- **2 GiB 内存装依赖会被 OOM 杀掉**，症状是只打印一行 `Killed`，很容易被误认成"装包失败"。解决：`pip3 install --no-cache-dir -r server/requirements.txt`。
- **服务必须重启才读得到 `.env`**：变量是 systemd 通过 `EnvironmentFile` 在启动时注入的，改完文件不 `systemctl restart groupintel` 等于没改。这是最容易浪费半小时的一条。
- 进程守护：`Restart=always` + `RestartSec=3`（`server/groupintel.service`），崩了自己爬起来，演示时不用守终端。

## 四、大模型输出的可靠性

模型经常不老实返回 JSON（前面加一句"好的"、外面裹一层 ```json），直接 `json.loads` 就整条链路崩。

- **提示词层面**：`SYSTEM_PROMPT` 明确"只输出一个 JSON 对象，不要解释文字，不要 markdown 代码块"，并给出固定字段结构（`server/summarize.py:8-19`）；`temperature=0.2` 降低发挥空间。
- **解析层面**：三级兜底 `_extract_json()`（`server/summarize.py:22-34`）——先直接 `loads`；失败就正则剥掉 ``` 围栏；再失败就取第一个 `{` 到最后一个 `}` 之间重试。
- **降级不失败**：实在解析不出来时返回 `degraded=True` + 原文当摘要（`server/summarize.py:54-64`），前端显示"模型未按结构化格式返回"角标（`web/app.js:51`）。**演示时界面照常出结果，不会白屏**。
- **成本控制**：输入超过 20000 字先截断并标注（`server/summarize.py:41-42`），避免有人粘一整年聊天记录进来把额度烧光。
- **错误语义分层**：空输入 → 400「群聊内容为空」；百炼调用失败 → 502 且带上服务器原始报错；未预期异常 → 全局 500 处理器（`server/app.py:61-62,88-89`）。前端能区分"你没填内容"和"服务器/百炼出问题"。

## 五、多人协作与访问控制

- **全员 root + 密码**（FinalShell），不分发密钥、不收公钥。好处是零配置、人人能改服务器文件；代价是**技术上无法单独撤销某个人**，只能改密码重通知，也**无法审计谁做了什么**。
- 因此把追责手段放在 git 上：**动手前 `git pull`，改完当天 `log_and_push.py --note "谁 + 改了什么"`**，note 里写名字。`/opt/groupintel` 被误删也能从 GitHub 的 `copies/` 快照和 `logs/` 恢复。
- **唯一的实质风险是 22 端口 + 密码 + 全网开放 = 爆破**。缓解方式是安全组把 22 的来源收成 5 个人的出口 IP（`x.x.x.x/32` 一人一条），删掉默认那条 `0.0.0.0/0` 的 SSH 规则；80/443/3389 等用不到的默认规则一并删。8000 保持全开（要给评委访问）。
- 诚实记录一条：**组员是 root，`cat /opt/groupintel/.env` 就能看到百炼 Key**。所以"Key 只留服务器"约束的是发给外人的客户端，组内它是流程约定而不是技术隔离。要真隔离就得开独立账号管文件属主，小组实验不做。

## 六、仓库与自动化踩过的两个真 bug

| 症状 | 根因 | 修复 |
|---|---|---|
| 每次重新部署后，百炼 Key 和 token 神秘消失 | `deploy.sh` 里 `cp -f .env.example .env` 无条件执行，而 tar 上传根本不含 `.env`，于是服务器上的真实配置被空模板覆盖 | 改成只在 `.env` 不存在时才生成：`[ -f .env ] \|\| cp -f .env.example .env`（`deploy.sh:31`） |
| 日志里第一个文件路径少一个字母（`roup-intel/README.md`） | `git status --porcelain` 的状态列是**固定宽度两列**，代码先对整段输出 `.strip()`，把首行前导空格吃掉后再 `line[3:]` 就切进了路径 | 保留原始输出、逐行判断非空：`[line[3:] for line in status.splitlines() if line.strip()]`（`scripts/log_and_push.py:67-68`） |

另外三条与"共享仓库"有关的约束，都是当时定下来的（仓库是 `lifeppppp/aigc_5`，本项目只在 `group-intel/` 子目录）：

- 暂存必须限定范围 `git add -A -- .`，否则会把组员在其他目录的未提交文件一起提交；
- 推送要显式带密钥 `GIT_SSH_COMMAND="ssh -i ~/.ssh/id_rsa -o IdentitiesOnly=yes"`，默认 ssh 不带 `-i` 会失败；
- 判断是否仓库用 `git rev-parse --is-inside-work-tree`，不能用 `.git` 目录是否存在——否则会在 clone 出来的仓库里再 `init` 出一个嵌套仓库。

## 七、还没验证的（别在汇报里说成已完成的）

1. **真实百炼那一跳**：代码在本机用 mock 验过全链路（鉴权 / 解析 / 降级 / 空输入 / 界面渲染），但**还没用真 Key 打过一次**。判定方法：服务器上 `curl http://127.0.0.1:8000/api/health` 看 `bailian_key_configured`，再打一发 `/api/summarize`。
2. **公网可达**：取决于安全组 8000 是否放行。分界规则——`127.0.0.1` 通而公网 IP 不通，就是安全组，跟 Key 无关。
3. **钉钉 Stream 与 webhook 回写**：代码写完，缺 AppKey/AppSecret 和机器人加签凭据，且企业应用可能要走管理员审核。
4. **真安装包**：exe / apk 都还没打。
5. **结果落库**：目前整理结果只在浏览器里，没有 sqlite 持久化和按周聚合，最后的总结素材还得靠 `logs/` + `copies/`。

## 八、汇报可以直接引用的三句话

1. **安全**：密钥只存在服务端 `.env`（600 权限），客户端拿到的是中转地址和一个可撤销的访问令牌，前端任何文件里都不含密钥。
2. **合规**：不绕过钉钉的群消息权限——只接收 @机器人 的消息和成员主动粘贴的记录，放弃了需要企业资质的会话存档。
3. **可追溯**：服务器上的每一次改动都会自动写一篇日志并附一份全量代码副本推到 GitHub，误删可恢复，责任可回溯。
